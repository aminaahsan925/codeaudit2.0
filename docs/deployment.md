# Deployment

LaunchAudit runs in two places: the backend API and the demo shops on
Render, the frontend on Vercel. The backend image is built from
`backend/Dockerfile`; Render provisions everything else from `render.yaml`
at the repo root.

## What you get

| Piece | Service | URL after deploy |
| --- | --- | --- |
| API | `launchaudit-api` (Render, Docker, free) | https://launchaudit-api.onrender.com |
| Database | `launchaudit-db` (Render Postgres, free) | internal only |
| Demo shop, broken | `launchaudit-demo-broken` (Render, Python, free) | https://launchaudit-demo-broken.onrender.com |
| Demo shop, fixed | `launchaudit-demo-fixed` (Render, Python, free) | https://launchaudit-demo-fixed.onrender.com |
| Frontend | Vercel project (Next.js) | https://<project>.vercel.app |

## 1. Deploy the backend on Render

1. Push the `feat/deploy` branch to GitHub.
2. In the Render Dashboard: New > Blueprint.
3. Connect the `aminaahsan925/codeaudit2.0` repo and pick the
   `feat/deploy` branch. Render reads `render.yaml` and lists the four
   resources above.
4. Render asks for values for the two `sync: false` variables
   (`CORS_ORIGINS`, `FRONTEND_URL`). The Vercel URL does not exist yet,
   so enter a temporary value for both (any valid URL, e.g.
   `https://example.com`) and fix them in step 3 below. Do not leave
   them empty: Render requires a value at Blueprint creation time.
5. Click Apply. The first build takes several minutes: the image
   installs Chromium and its system libraries.
6. When the API is live, check
   https://launchaudit-api.onrender.com/api/health returns
   `{"status":"ok","version":"0.1.0"}`. The start script runs
   `alembic upgrade head` before the server starts, so the database
   schema is created automatically; no manual migration step.

## 2. Deploy the frontend on Vercel

1. In the Vercel Dashboard: Add New > Project, import
   `aminaahsan925/codeaudit2.0`.
2. Set **Root Directory** to `frontend`. Framework Preset stays
   Next.js; Vercel detects pnpm from `pnpm-lock.yaml`.
3. Set the environment variable (Production):
   `NEXT_PUBLIC_API_BASE_URL=https://launchaudit-api.onrender.com`
   (no trailing slash). This is required: production builds fail
   without it.
4. Deploy. Note the app URL, e.g. `https://launchaudit.vercel.app`.

## 3. Point the backend at the frontend

Back in the Render Dashboard, open the `launchaudit-api` service >
Environment, and set both variables to the real Vercel URL (no
trailing slash):

- `CORS_ORIGINS=https://launchaudit.vercel.app`
- `FRONTEND_URL=https://launchaudit.vercel.app`

Save; Render redeploys the API. Until `CORS_ORIGINS` holds the real
Vercel origin, the browser cannot call the API (the browser blocks
cross-origin requests).

## 4. Check it works

1. Open the Vercel URL. The header shows the API status badge.
2. Run an audit against the broken demo shop:
   live URL `https://launchaudit-demo-broken.onrender.com`.
   Expect verdict Do not launch, risk about 8.3.
3. Run an audit against the fixed demo shop:
   live URL `https://launchaudit-demo-fixed.onrender.com`.
   Expect verdict Launch, risk about 1.0.
4. Open the shared report link from a run; it must load without
   signing in.

Note: Render free services spin down after about 15 minutes without
traffic. The first request after a sleep takes 30 to 60 seconds while
the service wakes up. The demo shops sleep too, so the first audit
after a quiet spell is slow. This is a free plan limit, not a bug.

## Environment variables

Backend (`launchaudit-api` on Render). Required ones are marked.

| Variable | Required | What it does |
| --- | --- | --- |
| `ENVIRONMENT` | yes | Must be `production` on Render. |
| `DATABASE_URL` | yes | Set from the `launchaudit-db` database by the Blueprint. Render hands out a `postgres://` URL; `backend/start.sh` rewrites it to the `postgresql+psycopg://` scheme the app config requires. |
| `SESSION_SECRET` | no | Signs session tokens. Generated by Render (`generateValue`). Without it (or shorter than 32 characters) sign-in is unavailable and the app still works with guest runs and demo sign-in. |
| `CORS_ORIGINS` | no | Comma-separated list of origins allowed to call the API from a browser. Must be the Vercel URL once the frontend is live. Defaults to localhost only. |
| `FRONTEND_URL` | no | Public origin of the frontend; the Google OAuth callback redirects here. Defaults to localhost. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | no | Google sign-in. All three must be set for it to work; see `docs/google-signin-setup.md`. Without them the app offers demo sign-in instead. `GOOGLE_REDIRECT_URI` must be `https://launchaudit-api.onrender.com/auth/google/callback` and must match the URI registered in Google Cloud. |
| `GEMINI_API_KEY`, `GROQ_API_KEY` | no | AI review providers (Gemini first, Groq backup). Without both, AI review uses the rule-based fallback. |
| `API_AUTH_TOKEN` | no | Never set this in production: the config rejects it there. It is a development and test stub only. |
| `LOG_LEVEL` | no | Defaults to `INFO`. |

Frontend (Vercel project).

| Variable | Required | What it does |
| --- | --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | yes | Public origin of the Render API, e.g. `https://launchaudit-api.onrender.com`. The browser calls the API directly at this origin. Required for production builds. |

## What is in the backend image

`backend/Dockerfile` builds on `python:3.12-slim` and adds:

- **Chromium + system libraries** (`playwright install --with-deps
  chromium`) so the Playwright journey runner works. Browsers live in
  `/ms-playwright`, owned by the non-root app user (uid 10001), because
  browsers installed under `/root/.cache` would be unreadable by that
  user.
- **git**, needed to clone GitHub repos for code scans.
- **gitleaks 8.30.1** (checksum verified, same version pinned in CI)
  for the git history secret scan.
- **osv-scanner 2.7.1** (checksum verified) for the dependency
  vulnerability scan.
- **semgrep is not installed.** It is too heavy for this image; the
  native rules cover its checks and the code reports it as skipped.

The image runs as non-root user 10001. Journey screenshots go to
`/app/artifacts`, which the image creates and hands to that user.
Startup (`backend/start.sh`) runs `alembic upgrade head`, then starts
uvicorn on `$PORT` (Render sets it; default 8000 locally).

## Limits of the free setup

- **Spin down:** Render free web services sleep after about 15
  minutes without traffic and take 30 to 60 seconds to wake. The API
  and both demo shops are affected.
- **Free Postgres expiry:** Render free PostgreSQL instances expire
  after 30 days and are deleted, audit history included. Before the
  30 days are up, either upgrade the database to a paid plan or accept
  losing the stored runs (the app recreates the schema on a fresh
  database automatically).
- **Ephemeral disk:** journey screenshots and uploaded zips live on
  the service disk and are lost on redeploy or restart. Shared report
  links keep working for the report text, but screenshots may be gone.
- **No Google sign-in until a Google client exists.** Creating the
  OAuth client in Google Cloud is a manual step (see
  `docs/google-signin-setup.md`). Until then, demo sign-in and guest
  runs work.
- **No AI review keys by default.** Add `GEMINI_API_KEY` (or
  `GROQ_API_KEY`) in the Render Dashboard to enable AI review;
  otherwise findings get the rule-based explanation.
- **Demo shops are intentionally insecure.** The broken variant
  carries a planted test secret and a failing checkout on purpose.
  They are demo targets only, never real shops, and their URLs are
  public.
- **One region, one instance.** Free services run a single instance;
  there is no redundancy.
